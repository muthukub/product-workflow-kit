# Lean product workflow for Codex

Nine specialized, project-scoped subagents produce consistent Markdown artifacts for:

Lean Canvas → Now / Next / Later Roadmap → Lean PRDs → Epics → User Stories / Enablers → RFCs / ADRs.

The main Codex agent coordinates dependencies and handoffs. The risk register is maintained alongside the workflow, starting at the Lean PRD stage. RFCs can move earlier when technical uncertainty blocks planning.

## Agents and outputs

| Agent | Responsibility | Standard template |
| --- | --- | --- |
| `lean_canvas` | Nine-block business model and validation assumptions | [Lean Canvas](templates/lean-canvas.md) |
| `product_roadmap` | Outcomes, Now/Next/Later priorities, promotion criteria | [Roadmap](templates/product-roadmap.md) |
| `lean_prd` | Bounded problem, scope, measures, risks | [Lean PRD](templates/lean-prd.md) |
| `risk_register` | Stable risk IDs, classification, routing, evidence | [Risk register](templates/risk-register.md) |
| `epic` | Cohesive outcome and delivery decomposition | [Epic](templates/epic.md) |
| `user_story` | User value, testable criteria, business/user risk validation | [User story](templates/user-story.md) |
| `enabler` | Technical deliverables and timeboxed spikes | [Enabler](templates/enabler.md) |
| `rfc` | Options, tradeoffs, experiments, proposal and resolution | [RFC](templates/rfc.md) |
| `adr` | One architecture decision, rationale and consequences | [ADR](templates/adr.md) |

## Start using the agents

Open this folder as the project in Codex and start a new chat so it can load the new project configuration and instructions. Use a trusted project: Codex skips project configuration for untrusted projects. The profiles are in [.codex/agents](.codex/agents); they inherit your parent model and permissions. The project configuration enables agents and caps concurrent subagents at three; the runtime may impose a lower limit.

These use the standalone custom-agent format in the current [official Subagents documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents). The local CLI reports version 0.153.4. See also the [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference). Older clients may require an upgrade or a different configuration format. File validation does not prove that a client has loaded the agents; request the smoke check below in the new chat.

Copy a prompt from [examples/prompts.md](examples/prompts.md). Supply your product brief as a file or directly in the chat. Outputs will be created under `products/<product-slug>/`; no product-specific content is generated by installing this kit.

```text
Use lean_canvas to create a Lean Canvas for <product> from <brief path>.
Use templates/lean-canvas.md and the shared workflow contract.
Save it under products/<slug>/ and return evidence gaps and next steps.
```

To use this kit in another repository, copy `AGENTS.md`, `.codex/agents/`, `templates/`, `workflow/`, and optionally `scripts/` and `examples/`. Merge the instructions into an existing AGENTS.md and merge the `[agents]` settings into existing `.codex/config.toml`; preserve existing rules and other configuration. Do not replace a repository's existing instructions wholesale.

## Risk routing

At the PRD stage, the PRD specialist identifies risks and the register specialist assigns stable IDs. The coordinator reconciles the IDs into source and destination documents.

| Risk category | Required destination | What the output must contain |
| --- | --- | --- |
| Business or user | User story | Observable behavior or learning outcome; hypothesis, method, threshold and next decision |
| Technical, evaluation needed | RFC | Alternatives, tradeoffs and evidence-producing evaluation |
| Technical, decision to record | ADR | Proposed or authorized decision, rationale, consequences and validation |

A technical enabler can implement a decision or investigate uncertainty, but the technical risk retains its RFC/ADR route. An RFC and an ADR have distinct jobs; both are useful when evaluation leads to an enduring decision, but both are not mandatory for every risk.

Risk links are reciprocal. Creating a document does not close a risk. Closure requires evidence against an explicit criterion. Acceptance of a risk or architectural decision requires a real authorized decision; agents can draft proposals freely.

## Quality and customization

[workflow/CONTRACT.md](workflow/CONTRACT.md) defines IDs, metadata, evidence, lifecycle, risk rules and traceability. [workflow/ORCHESTRATION.md](workflow/ORCHESTRATION.md) defines dispatch payloads, dependency order, ownership and completion criteria. The main agent owns the index; one agent writes the risk register, preventing concurrent register edits.

To change output structure, edit its template and keep the corresponding profile consistent. To add a specialist, add its TOML profile, template, routing row and validator mapping. Model overrides are intentionally omitted; add them only for models supported by your account/client.

Run:

```powershell
python scripts/validate-kit.py
```

The check parses all TOML files and verifies profile fields, template paths, required metadata, headings and repository document links. Python 3.11+ uses `tomllib`; Python 3.10 can use installed `tomli` or pip's bundled parser. It does not assess product quality, run model evaluations, or validate generated product artifacts. The coordinator performs artifact content and routing checks using the runbook.
